Gamepad

Play with a physical pad. Connect it and press any button, because browsers hide a pad until it's used. The label over the game shows what the browser reports, live. Every demo on this site works with a pad.

  • Stick or D-pad Move
  • A / ✕ Jump
  • X / □ Dash
  • Down + A Drop through a one-way platform

Using it

game.gamepad.enabled = true;

game.gamepad.isConnected;
game.gamepad.deadZone = 0.3;   // how far a stick must move
game.gamepad.vibrate(0.2, 0.6); // seconds and strength, if the pad can

Like the on-screen buttons, a pad presses keyboard keys, so Player and your code don't change. Only the game with focus reads it.

Pads with their own layout

Well-known pads are reported as "standard", with the same numbers everywhere. Many generic USB pads have their own layout, and numbers vary with the model and the system. Press each control here, note the numbers in the label, and map them:

game.gamepad.setMapping({
  buttons: { Space: [2], KeyX: [3], ArrowDown: [] },
  moveAxes: [[0, 1], [5, 6]],  // the stick, and a D-pad reported as axes
});
FieldDefaultDescription
buttonsSpace: 0, KeyX: 2, D-pad: 13–15For each key, the buttons that press it.
moveAxes[[0, 1]]Pairs of axes that work as left/right and up/down.
directions←, → and ↓The keys for each direction. Up presses nothing by default.

On this site, you can change the pad's controls on the Controls page. game.gamepad.getState() returns { id, mapping, pressed, axes }, which is what the label shows. Only the first connected pad is read.
