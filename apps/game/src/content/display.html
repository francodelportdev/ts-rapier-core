Screen size and sharpness

The canvas renders at the screen's pixel density, so it looks sharp on phones and high-density monitors. You don't have to do anything, and your coordinates don't change: draw(), the camera and game.pointer keep working in the same pixels.

const game = await Game.create(canvas, { maxPixelRatio: 2 });

game.width;            // the size to work with, in pixels
game.height;
game.resize(1024, 576); // change it
MemberDescription
maxPixelRatioThe highest density to render at. The default is 2, and 1 turns it off. Higher values draw more pixels, so lower it if a phone struggles.
game.width, game.heightUse them instead of canvas.width, which also includes the density.
game.resize(width, height)Changes the size of the view. It doesn't follow the page by itself: for a full-screen game, call it when the window resizes.

Smooth movement

Physics runs at 60 steps per second, whatever the screen. On a 144 Hz monitor, some frames would have no new step, so movement would look uneven. The engine draws entities and the camera between the last two steps, which keeps it smooth. It's on by default and needs no changes in draw(), sprites or components. It adds a delay of less than one step (16 ms). Turn it off with Game.create(canvas, { interpolation: false }) or game.interpolation = false.

Jumps of more than 2 m in a step, such as a respawn, aren't smoothed. The debug view shows the real bodies, so outlines can be slightly ahead of what's drawn.

If the window moves to a screen with another density, the canvas adjusts on its own. A canvas sized by CSS, such as width: 100%, stays responsive.
